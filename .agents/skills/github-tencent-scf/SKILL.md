# GitHub 部署腾讯云函数

将静态站点构建为 SCF Web 函数代码包，用 GitHub Actions 和腾讯云 Python SDK 更新代码，不使用 Serverless Framework、Serverless 应用部署能力或第三方 Serverless Action。适用于首次部署和迁移；其他类型项目须先判断其运行方式，不能盲套静态站点模板。

## 确认目标与访问权限

1. 根据用户提供的 GitHub 链接核实仓库、默认分支、代码和现有工作流；链接也可能指向技能仓库，不要误当目标仓库。检查构建命令、产物目录以及现有部署是否仍在使用。优先使用已连接的 GitHub 工具；能力不足时使用已授权的浏览器或 CLI。
2. 使用内置浏览器打开腾讯云控制台，检查登录状态和实际账号；未登录或需要验证时让用户自行登录，完成后继续。浏览器登录不等于 SDK 凭据可用。若无法访问内置浏览器，如实说明并引导用户完成相关控制台操作，不声称已验证。
3. 用户未说明站点名称时询问名称；区分展示名称和 SCF 函数资源名，函数名遵循腾讯云当前命名规则。检查地域、命名空间和现有资源，优先沿用用户指定或现有配置；不能从仓库名称推断既有函数名称。对于新资源选择合理默认值并告知用户，无法确定时询问。自定义域名仅在用户提出或提供域名时配置。
4. 检查仓库和工作流使用的环境是否有 `TENCENT_SECRET_ID` 和 `TENCENT_SECRET_KEY`，同时检查组织级权限和环境保护规则。Secrets 的值不可读取；存在名称不代表值有效、作用域正确或权限足够，最终以部署结果为准。不可见时说明无法核实，询问用户是否已配置。
5. 如缺少密钥，引导用户在目标 GitHub 仓库 **Settings → Secrets and variables → Actions → New repository secret** 分别添加 `TENCENT_SECRET_ID`（腾讯云 SecretId）和 `TENCENT_SECRET_KEY`（SecretKey）；说明工作流若使用 environment，还要检查环境级 Secrets。用户在腾讯云访问管理控制台获取或创建适当权限的密钥，并自行粘贴到 GitHub；不要求用户在对话、命令行或日志中提供密钥，不读取或输出密钥值。优先使用权限最小化的子账号。

## 首次部署

1. 根据项目实际情况准备构建命令和静态资源目录。参考 [assets/app.js](assets/app.js)、[assets/scf_bootstrap](assets/scf_bootstrap)：Web 服务监听 `0.0.0.0:9000`，资源放在 `public/`，启动文件位于 ZIP 根目录且有执行权限。该示例是 Node 静态服务器，只适用于静态站；根据路由、资源类型及安全需求调整。`scf_bootstrap` 中的 Node 路径必须按所选腾讯云运行时核实并改写，不能照搬示例的 Node 16 路径。
2. 在腾讯云控制台选择目标地域和命名空间，创建标准 SCF **Web 函数**，使用当前可新建且受支持的 Node.js 运行时（优先评估 Node.js 20.19 或更新版本），配置内存、超时和公网访问入口。避免创建同名资源或覆盖非目标函数。首次创建可通过控制台完成；之后代码更新必须走 Python SDK。创建过程若要求支付、实名或授权，让用户处理对应步骤。
3. 配置并验证可访问的入口：优先在控制台为函数启用公网函数 URL；如不支持则配置 API 网关触发器并发布。记录实际 URL、地域、版本或别名及鉴权设置。已有入口按实际类型保留，不要把 API 网关域名与函数 URL 混为一谈。
4. 参考 [assets/tencent-scf.yml](assets/tencent-scf.yml) 和 [assets/deploy.py](assets/deploy.py) 生成适配目标项目的工作流和 SDK 脚本。示例来自已有项目：必须替换脚本里的 `siss`、`ap-nanjing`、`default`，适配分支、构建、依赖管理、输出目录、运行时和路径，绝不直接部署到示例资源。脚本仅调用 GetFunction 和 UpdateFunctionCode，不创建函数或改变配置。检查 ZIP 大小；直接上传接口限制以当前文档为准（示例限制 20 MiB），超限改用官方支持的 COS 方式或说明阻碍。压缩时从包根目录打包，保留启动文件权限。
5. 将改动提交并推送到用户授权的目标分支，必要时以手动触发运行工作流；监测 GitHub Actions 的结果。仅在用户授权范围内修改远程仓库和云资源，遵循当前环境的权限要求。函数恢复 Active 并不单独证明站点可用，检查代码更新结果后访问首页和至少一个静态资源；SPA 刷新、子路径和自定义域名按项目实际验证。记录运行链接、函数和访问 URL；失败时检查日志但不泄露密钥，准确报告未完成步骤。

## 从 Serverless 迁移

先检查 Serverless 配置、工作流及腾讯云控制台，记录函数名、地域、命名空间、运行时、代码、环境变量、网络、层、触发器、API 网关、域名、版本/别名及关联资源。使用现有函数，不因迁移而重新创建；核实其类型和版本支持目标更新方式。保留原 `serverless.yml` 等编排文件作为配置备份，停用原部署入口，避免两条流程互相覆盖；不要删除资源或改动触发器。适配 SDK 工作流后验证实际线上入口、静态资源、日志及原路由；保留上一个可部署代码包和回滚方式。无法安全确定目标或执行更新时停止并说明。

## 自定义域名

用户要求时，根据现有入口类型操作其所属控制台：函数 URL 的自定义域名在 SCF 配置路径映射；API 网关入口在网关控制台配置对应绑定与发布。核实同地域、域名备案及 HTTPS 证书等实际条件。CNAME 值以对应控制台显示的值为准，告诉用户 DNS 记录主机名、类型和目标；没有实际值时不得猜测。DNS 完成后验证解析和 HTTPS。
